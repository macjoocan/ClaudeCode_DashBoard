# Claude Code 세션 런처

여러 프로젝트에 흩어진 Claude Code 세션을 **한 페이지에서 보고, 상태를 확인하고,
그 페이지 안에서 여러 개를 동시에 띄워 작업하고, 하네스 설정까지 한눈에 점검**하는 로컬 대시보드.
Claude Code 뿐 아니라 OpenAI Codex 세션도 같은 화면·같은 방식으로 다룬다.

주소: http://127.0.0.1:7788 (127.0.0.1 전용 - 외부에 노출되지 않는다)

## 실행

**바탕화면 바로가기 한 번 클릭**이 기본이다. 처음 받은 PC 에서는:

```
wscript MakeShortcut.vbs     # 바탕화면에 "Claude 세션 런처" 바로가기 생성 (한 번만)
```

그 다음부터는 바로가기를 누르면 된다. `Launch.vbs` 가 하는 일:

1. 서버가 **이미 돌고 있으면** 브라우저만 연다 (포트 충돌 없음)
2. 안 돌고 있으면 의존성을 확인하고 **창 없이** 서버를 띄운 뒤, 응답할 때까지 기다렸다가 브라우저를 연다
3. Node.js 가 없으면 안내 창을 띄운다

| 파일 | 하는 일 |
|---|---|
| `Launch.vbs` | 클릭 한 번 실행 (콘솔 창 없음). 바로가기가 이걸 가리킨다 |
| `Stop.vbs` | 이 폴더의 서버만 골라 종료. 다른 node 프로그램은 건드리지 않는다 |
| `MakeShortcut.vbs` | 바탕화면 바로가기 생성 (PC 마다 한 번) |
| `run.bat` | 콘솔 창을 띄워 로그를 보며 실행 (문제 확인용) |
| `run-hidden.vbs` | 창 없이 서버만 시작 (브라우저 안 열음) |

- 작업표시줄 고정: 바로가기 우클릭 → 작업 표시줄에 고정
- 윈도 시작 시 자동 실행: `Launch.vbs` 바로가기를 `shell:startup` 폴더에 넣기
- 포트 변경: `set CC_LAUNCHER_PORT=9000`
- 의존성(node-pty, ws)은 첫 실행 때 자동 설치된다

**Node 버전** — 이 프로젝트는 Node.js **v24.13.0** 에서 개발·테스트됐다. Codex 세션
목록을 읽을 때 `node:sqlite` 를 쓰는데, 이게 최신 Node 를 요구하는 이유다. 공식 문서
기준 `node:sqlite` 는 v22.5.0 에서 `--experimental-sqlite` 플래그와 함께 처음 추가됐고,
플래그 없이 쓸 수 있게 된 건 v22.13.0(22.x) / v23.4.0(23.x) 부터다 — 이 코드는 플래그를
넘기지 않으므로 최소 그 버전은 필요하다. 다만 실제로 돌려본 건 v24.13.0 뿐이고, 그 사이
버전에서의 동작은 확인하지 않았다.

> `.vbs` 파일은 **UTF-16 + BOM** 으로 저장한다. WSH 는 BOM 없는 파일을 ANSI 로 읽어서
> 한글 메시지가 깨진다.
>
> 배치 스크립트 이름이 `start.bat` 이 아닌 이유: cmd 의 내장 `start` 명령과 헷갈려
> 엉뚱하게 실행되는 사고를 막기 위해 `run.bat` 으로 뒀다.

## 탭 7개

| 탭 | 보여주는 것 |
|---|---|
| **전체** | 프로젝트별 카드. 각 카드에 최근 세션 3개(+더 보기) |
| **즐겨찾기** | ★ 표시한 세션만 카드로. 자주 쓰는 세션 바로 열기용 |
| **실행 중** | 지금 살아있는 세션만. 작업 중 / 대기 중 + PID |
| **터미널** | 대시보드 안에서 도는 세션들. 1/2/3/4/전체 분할 |
| **실황** | 세션·서브에이전트 활동 워터폴 타임라인 (실시간) |
| **연결** | 프로젝트 → 세션 → 서브에이전트 그래프 + 실시간 신호 |
| **구성** | 하네스 설정 전체 (권한·훅·MCP·플러그인·스킬) + 점검 결과 + **편집** (Codex 는 `codex doctor` 기반 읽기 전용) |

카드는 프로젝트(폴더) 기준으로 하나만 만들어진다. 같은 폴더에서 Claude Code 세션과
Codex 세션이 둘 다 있으면 카드 하나 안에 `Claude Code` / `Codex` 두 그룹으로 나뉘어
들어간다. Codex 는 cwd 를 확장 길이 경로(`\\?\D:\...`)로 저장하는데, 벗기지 않으면
Claude 쪽과 다른 키가 되어 카드가 둘로 갈리므로 정규화해서 맞춘다.

## 폴더 지정해서 실행

목록 도구 막대의 **📁 폴더 지정 · Claude** / **Codex** 를 누르면 윈도 기본 폴더 선택
창이 뜨고, 고른 폴더에서 새 세션이 시작된다. **세션 기록이 없는 새 폴더도 된다** —
대시보드에 카드가 없는 폴더에서 처음 작업을 시작할 때 쓴다.
실행 위치(대시보드 / 새 창)는 헤더의 설정을 그대로 따른다.

왜 서버가 창을 띄우나: 브라우저에는 **진짜 폴더 경로를 주는 표준 방법이 없다.**
`<input webkitdirectory>` 는 파일 이름만 주고 절대 경로는 주지 않는다. 그래서 서버가
`FolderBrowserDialog` 를 띄우고 경로를 돌려준다(`POST /api/pickfolder`).

- 대화상자가 브라우저 뒤로 숨지 않게 항상 위에 있는 1×1 폼을 소유자로 준다
- 마지막에 고른 폴더에서 다음 번 창이 열린다
- 취소하면 아무 일도 안 일어난다 (`{cancelled:true}`)
- 3분 안에 안 고르면 시간 초과로 접는다
- PowerShell 스크립트는 **ASCII 로만** 쓴다. PS 5.1 은 BOM 없는 입력을 ANSI 로 읽어
  한글이 깨진다 — 한국어 안내는 서버 쪽 메시지로 낸다

> 신뢰하지 않는 새 폴더를 고르면 Claude Code 가 터미널 안에서 "이 폴더를 믿습니까"
> 를 먼저 묻는다. 그건 CLI 자체 동작이라 패인 안에서 답하면 된다.

## 문서 탭 — 마크다운 편집기 (SCRIBE)

웹 터미널에서 만든 `.md` 를 대시보드 안에서 바로 열고 고친다.
**문서** 탭에서 보관 폴더를 고르면 그 폴더의 마크다운이 트리로 뜬다.

- 프로젝트 드롭다운으로 세션이 있는 폴더를 바로 고르거나, `📁 폴더 고르기` 로 아무 폴더나
- **터미널에서 새로 만든 파일이 3초 안에 목록에 나타난다**
- `Ctrl+S` 로 저장하면 그 자리에서 디스크에 쓰인다
- 저장 안 하고 닫아도 초안이 남는다

### 어떻게 끼워 넣었나

편집기는 **SCRIBE**(별도 프로젝트: React + Vite + CodeMirror 6 로 만든 마크다운 편집기)
의 **빌드 결과물을 그대로** 쓴다. 소스는 한 줄도
고치지 않았다. 가능한 이유는 SCRIBE 가 파일에 닿는 통로를 `window.scribe` 하나로
좁혀 놨기 때문이다 (Electron 에서는 preload 가 넣어주던 객체).

```
SCRIBE dist  →  window.scribe  →  /api/md  →  SCRIBE 의 desktop/vault.cjs
 (그대로)       (브리지 교체)      (런처)        (그대로 require)
```

| 조각 | 하는 일 |
|---|---|
| `scribe.js` | 보관 폴더 상태 + 브리지 동작. 파일 입출력은 SCRIBE 의 `vault.cjs`·`search.cjs` 를 **그대로 require** 한다 |
| `public/scribe-bridge.js` | `window.scribe` 를 HTTP 로 구현. 서버가 `index.html` 에 끼워 넣어 앱 번들보다 먼저 돈다 |
| `/scribe/*` | `editor/dist` 를 그대로 내려준다 |

베끼지 않고 require 하는 이유: 복사하면 SCRIBE 가 고쳐질 때 조용히 갈라진다.
그 두 파일은 Electron 을 참조하지 않는 순수 Node 라 그냥 불러진다 — 경로 탈출과
심링크 방어도 거기 들어 있어 그대로 얻는다.

**SCRIBE 위치**는 자동으로 찾는다: `<런처 상위>\Scribe\editor` → `~\Scribe\editor` 순서.
다른 곳에 있으면 환경변수 `CC_SCRIBE_DIR` 로 알려준다. `editor\dist` 가 있어야 한다
(`npm run build`). 못 찾으면 문서 탭이 그 사실과 해결법을 띄운다 — 나머지 기능은 멀쩡하다.

### 다른 점

Electron 에서만 되던 두 가지는 브라우저에서 빠진다.

- **HTML/PDF 내보내기** — 저장 대화상자가 필요해 `null` 을 돌려준다 (SCRIBE 가 취소로 보고 넘어간다)
- **파일 감시** — `fs.watch` 대신 3초마다 값싼 지문을 비교한다. 탭이 안 보이면 쉰다

보관 폴더 안의 삭제는 지우지 않고 `~/.claude/cc-launcher-scribe/trash/` 로 옮긴다.
설정·초안도 거기 있어서 런처를 다시 받아도 남는다.

## 세션 숨기기 · 삭제

쓸데없이 만든 세션이 쌓이면 목록이 지저분해진다. 두 가지 방법이 있다.

**숨기기 (`○`)** — 파일은 그대로 두고 목록에서만 뺀다. 세션 하나도, 프로젝트도
통째로 숨길 수 있다. 도구 막대의 `숨김 …` 을 누르면 다시 보이고, `모두 해제` 로
한 번에 되돌린다. 목록은 `hidden.json` 에 남는다.

> **실행 중인 것은 숨겨도 계속 보인다.** 지금 도는 세션이 화면에서 사라지면 찾을
> 길이 없어진다. 대신 `숨김` 꼬리표가 붙어 왜 아직 보이는지 알 수 있다.

**삭제 (`🗑`)** — 세션 기록 `.jsonl` 을 지우지 않고 **휴지통으로 옮긴다.**
서브에이전트 기록 폴더도 같이 간다. 즐겨찾기·숨김 목록에서도 빠진다.

```
~/.claude/.cc-launcher-trash/<날짜시각>_session-<id 앞 8자>/
```

- 되돌리려면 그 폴더의 `.jsonl` 을 `~/.claude/projects/<슬러그>/` 로 옮기면 된다
- **실행 중인 세션은 삭제 버튼이 비활성**이다. 쓰고 있는 기록 파일을 치우면 그 세션이 깨진다
- Codex 세션은 아직 삭제할 수 없다 (기록이 SQLite 라 파일 하나를 옮기는 것으로 끝나지 않는다)
- 슬러그·ID 를 정규식으로 검사하고, 조립한 경로가 `projects` 밖으로 나가지 않는지
  `path.resolve` 로 한 번 더 확인한다 (`SAFE_SLUG` 는 점을 허용해서 `..` 이 통과한다)

## 목록 줄이기 (접기 · 보기 방식 · 정렬)

세션이 쌓이면 카드가 벽이 된다. 목록 위 도구 막대로 줄인다.
**전체 / 즐겨찾기 / 실행 중** 세 탭에 다 붙어 있고, 고른 값은 브라우저에 남는다.

**접기** — 두 단계로 접는다.

| 어디를 누르나 | 무엇이 접히나 |
|---|---|
| 카드 머리글의 `▾` | 그 프로젝트 카드 전체. 이름·경로·브랜치·세션 수·실행 상태·토큰 사용량은 남는다 |
| 묶음 이름표(`▾ Claude Code 3`) | **그 묶음만.** Claude 만 펴두고 Codex 는 접어둘 수 있다 |

`전체 접기` 는 **카드만** 접는다. 묶음까지 접어두면 카드 하나를 폈을 때 안이 텅 비어
보여서 놀란다. `전체 펼치기` 는 카드든 묶음이든 다 편다. 둘 다 지금 화면에 있는
것에만 적용된다(검색으로 걸러낸 카드는 건드리지 않는다).

**보기 방식**

| | 설명 |
|---|---|
| 카드 | 지금까지의 보기 |
| 조밀 | 여백을 줄이고 한 줄에 더 많이 넣는다 |
| 목록 | 카드 틀을 벗고 한 줄씩. 마지막 프롬프트·본문을 숨긴다 |

**정렬** — 최근 / 이름 / 세션 수 / **직접**. 상단 고정(★)한 프로젝트와 실행 중인
세션은 정렬과 상관없이 늘 위에 온다.

**직접 순서 잡기** — 전체 탭에서 카드 머리글의 `⠿` 를 잡고 다른 카드 위로 놓으면
그 자리로 들어간다. 아무 카드나 끌면 정렬이 자동으로 `직접` 으로 바뀐다 — 안 그러면
끌어도 다음 렌더에서 원래 정렬로 되돌아가 "드래그가 안 먹는" 것처럼 보인다.

- 끌기 시작할 때 **지금 화면 순서를 그대로 굳혀** 기준으로 삼는다. 그래야 한 장만
  옮겼는데 나머지가 뒤엉키지 않는다
- 처음 보는 프로젝트는 최근순으로 뒤에 붙는다
- `직접` 모드에서는 고정(★)도 위로 끌어올리지 않는다. 손으로 놓은 자리가 우선이다
- 순서는 브라우저에 남는다 (`ccl.porder`)

실측 (프로젝트 18개 · 세션 199개 기준, 목록 전체 높이):

| | 높이 |
|---|---|
| 카드 (기본) | 9,337px |
| 목록 | 4,773px |
| 조밀 | 2,900px |
| 목록 + 전체 접기 | 1,034px |
| **조밀 + 전체 접기** | **425px** |

조밀이 목록보다 짧은 건 조밀은 여러 열로 깔고 목록은 한 줄에 하나씩 쌓기 때문이다.
목록은 높이를 줄이려는 게 아니라 **훑어보기** 위한 것이다.

## 대시보드에서 직접 작업하기

헤더의 **실행 위치** 를 `대시보드` 로 두면, 모든 실행 버튼이 **페이지 안의 터미널**에서
세션을 연다. `새 창` 으로 바꾸면 예전처럼 Windows Terminal 새 탭에서 열린다.

- **진짜 터미널이다.** node-pty(ConPTY) + xterm.js 로 실제 PTY 를 붙였다. Claude Code TUI 가
  그대로 뜨고, 권한 승인 프롬프트·폴더 신뢰 확인·슬래시 명령 자동완성·`shift+tab` 모드 전환·
  Ctrl+C 가 전부 정상 동작한다.
- **브라우저를 닫아도 세션은 산다.** PTY 를 서버가 소유하므로 새로고침하거나 창을 닫고
  다시 들어와도 스크롤백(최근 512KB)을 되살려 이어서 본다. 연결이 끊기면 3초 후 자동 재접속.
- **여러 개를 동시에 본다.** `개수`(1/2/3/4/전체) 와 `방향` 을 따로 고른다:

  | 방향 | 배치 | 좋을 때 |
  |---|---|---|
  | **가로** | 좌우로 나란히 `[A][B][C]` | 넓은 출력·긴 명령 |
  | **세로** | 위아래로 쌓기 | 대화 흐름을 길게 보기 |
  | **가로세로** | 정사각형에 가깝게 `2x2` | 3개 이상을 균형있게 |

  격자에서 마지막 줄이 비면 마지막 패인이 남은 칸을 채운다(구멍 없음).
  보이는 패인만 PTY 크기를 다시 맞추고, 입력은 클릭한 패인에만 들어간다.
  패인 머리글의 `⤢` 는 그 터미널만 크게 보기, `✕` 는 세션 종료. 선택은 저장된다.
- 탭 바에서 화면에 올라와 있는 터미널은 테두리로 구분되고, 클릭하면 화면으로 끌어온다.

### 복사 · 붙여넣기 (cmd 와 같은 방식)

| 키 | 동작 |
|---|---|
| 드래그 | 텍스트 선택 (보통은 이대로 된다) |
| **Shift + 드래그** | **선택이 안 될 때** — 아래 설명 참고 |
| 더블클릭 / 트리플클릭 | 단어 / 줄 선택 |
| `Ctrl+Shift+A` | 전체 선택 |
| `Ctrl+C` | 선택이 있으면 **복사**, 없으면 중단(SIGINT) |
| `Ctrl+Shift+C` · `Ctrl+Insert` | 항상 복사 |
| `Ctrl+V` · `Ctrl+Shift+V` · `Shift+Insert` | 붙여넣기 |
| 우클릭 | 선택이 있으면 복사, 없으면 붙여넣기 |
| 가운데 클릭 | 붙여넣기 |

**언제 Shift 가 필요한가**: 앱이 마우스 추적을 켜면 드래그가 선택이 아니라 앱 입력으로
간다. Claude Code TUI 는 실행 중에 마우스를 쓰므로 그럴 때 드래그로 선택이 안 된다.
xterm 은 `shouldForceSelection` 에서 Shift 를 보고 선택으로 되돌려주므로,
**그때만 Shift 를 누른 채 끌면** 된다 (Windows Terminal 도 같은 규칙).
마우스를 안 쓰는 화면(신뢰 확인 프롬프트, 일반 셸)에서는 그냥 드래그로 선택된다.

구현에서 손댄 두 가지 (`term.js` 의 `wireClipboard`):

1. **`Ctrl+C`** — xterm 은 선택이 있든 없든 항상 `` 을 보낸다. 선택이 있을 때만
   가로채 복사하고 선택을 해제한다(다음 `Ctrl+C` 는 다시 중단으로 간다). 선택이 없으면
   손대지 않고 그대로 통과시킨다
2. **`Ctrl+V`** — xterm 이 ``(Ctrl+V 제어문자)을 PTY 로 보내면서 `preventDefault` 까지
   해버려 **브라우저의 기본 붙여넣기가 아예 일어나지 않았다.** 커스텀 핸들러에서 `false` 를
   돌려주면 xterm 이 손을 떼고 preventDefault 도 하지 않으므로, 브라우저가 평소처럼
   붙여넣고 그 `paste` 이벤트를 xterm 이 받아 PTY 로 흘린다(괄호 붙여넣기로 감싸짐).
   클립보드 읽기 권한이 필요 없다

### 이미지 · 파일 넣기

터미널에 **이미지를 붙여넣거나(`Ctrl+V`) 파일을 끌어다 놓으면**, 그 파일이 저장되고
**경로가 프롬프트에 찍힌다.** 뒤에 질문을 이어 쓰면 된다.

```
❯ C:\Users\…\Temp\cc-launcher\paste\20260909-122809-secret.png 이 이미지 뭐라고 써있어?
```

여러 개를 한 번에 놓아도 되고, 이름에 공백이 있으면 따옴표로 감싼다.
끌고 오면 패인이 초록으로 바뀌며 "놓으면 파일 경로를 넣습니다" 가 뜬다.

**왜 경로로 넘기나** — PTY 는 텍스트만 흘리는 통로다. 이미지 바이트를 그대로 밀어넣을
방법이 없다. 브라우저도 보안상 끌어온 파일의 **진짜 경로를 알려주지 않아서**(파일 이름만
준다) 내용을 서버에 올려 새로 저장하는 수밖에 없다. 공식 문서가 말하는
"Provide an image path to Claude" 방식과 같다.

| | |
|---|---|
| 저장 위치 | `%TEMP%\cc-launcher\paste\<날짜시각>-<이름>` |
| 최대 크기 | 32MB (넘으면 413 과 함께 이유를 알려준다) |
| 이름 처리 | 경로 요소·금지문자를 걷어내고 저장 폴더 안에만 쓴다 |

> **`Alt+V` 는 이 터미널에서 안 통한다.** 공식 문서상 윈도에서 CLI 가 클립보드 이미지를
> 직접 읽는 키인데, 실측해 보면 `\x1bv` 가 PTY 까지 정확히 전달되는데도 CLI 가 이미지를
> 집지 않았다(클립보드에 이미지가 확실히 있는 상태에서 확인). 그래서 CLI 의 클립보드
> 경로에 기대지 않고 대시보드가 직접 처리한다. `Ctrl+V` 로 쓰면 된다.

### 자리 옮기기 · 크기 조절 · 새로고침 · 재시작

**자리 옮기기** — 세 가지 방법이 있다. 머리글 왼쪽의 숫자가 지금 몇 번째 칸인지다.

| 방법 | 설명 |
|---|---|
| `◀` `▶` 버튼 | 한 칸씩 앞뒤로. 끝에 닿으면 비활성된다 |
| `Alt+←` `Alt+→` | 터미널에 입력하는 중에도 된다 |
| 머리글(`⠿`) 드래그 | 다른 패인 위로 놓으면 그 자리로 들어간다 (스왑이 아니라 삽입) |

탭 바 순서도 같이 움직이고, 정한 순서는 브라우저에 남는다.

> **grid 는 DOM 순서로 배치한다.** `order` 배열만 바꾸면 자리 번호와 탭 순서는 바뀌는데
> 화면의 좌우 위치는 그대로다 — 자리 옮기기가 "안 먹는" 것처럼 보인다.
> 각 패인에 CSS `order` 를 넣어야 grid 가 그 순서로 배치한다.
> DOM 을 실제로 옮기지 않으므로 xterm 캔버스가 다시 그려지지 않는다.

순서 복원은 **첫 동기화에서 한 번만** 한다. 매번 하면 `apply()` 가 활성 패인을 앞으로
끌어온 것을 4초마다 되돌려버린다.

**크기 조절** — 패인 사이 틈을 끌면 그 경계의 두 칸 비율이 바뀐다. 세로 경계는 좌우,
가로 경계는 위아래. 최소 140px 까지만 줄어든다. **더블클릭하면 그 줄만 균등**해지고,
탭 바의 `크기 초기화` 는 전부 되돌린다.

칸 수마다 따로 기억한다(`grid:2x2`, `cols:3x1` …). 2분할에서 잡은 비율은 4분할에
갔다 와도 그대로다.

손잡이는 grid 자식이 아니라 **absolute 오버레이**다. grid 자식으로 넣으면 패인 자동
배치에 끼어들어 칸이 밀린다. 위치는 `getComputedStyle` 의 `gridTemplateColumns` 가
돌려주는 해결된 픽셀값에서 계산한다.

드래그 중 `fit()` 은 80ms 로 솎아낸다. 매 프레임 돌리면 무겁고, 아예 안 하면 캔버스가
잘려 보인다.

**↻ 새로고침** — 화면만 다시 붙인다. WebSocket 을 닫고 다시 열면 서버가 스크롤백을
되돌려주므로 내용은 그대로다. 출력이 깨져 보이거나 연결이 조용히 죽었을 때 쓴다.
세션·프로세스는 건드리지 않는다.

**⟳ 재시작** — CLI 프로세스만 갈아끼운다. 터미널 id 를 그대로 쓰기 때문에 **자리·크기·
탭 순서가 유지된다.** 세션 ID 를 확보한 상태면 `--resume` 으로 같은 대화를 이어서 켠다.

```
재시작 전  pid=46060  action=resume  sid=875ee242-…
재시작 후  pid=29052  action=resume  sid=875ee242-…   restarts=1
```

주의할 점 두 가지:

- **응답을 받는 중이면 그 응답은 사라진다.** 작업 중(busy)일 때는 물어본다
- 새 세션은 대화가 시작돼야 `sessionId` 가 생긴다. 그 전에 재시작하면 이어붙일 게
  없으므로 새로 시작한다 (`~/.claude/sessions/<pid>.json` 은 대화가 시작될 때 만들어지고,
  그 전에는 `.key` 파일만 있다)

구현에서 조심한 곳 — `terminals.js` 의 `wire()` 에 있는 `t.proc !== p` 검사다.
재시작하면 옛 프로세스의 `onExit` 이 kill 직후가 아니라 **새 프로세스를 꽂은 뒤에**
도착할 수 있다. 그걸 걸러내지 않으면 방금 띄운 터미널이 "종료됨"으로 표시된다.

## 사용 한도 (헤더)

`/usage` 가 보여주는 그 정보다. 헤더 왼쪽에 플랜과 두 게이지가 붙는다.

```
플랜        5시간  3시간 49분 뒤    주간  3일 20시간 뒤
Team 5x     8%   ▁▁▁▁▁▁▁▁         80%  ████████▁▁
```

- 60% 넘으면 노랑, 85% 넘으면 빨강
- 마우스를 올리면 모델별 한도까지 전부, 리셋 시각은 현지 시간으로
- `●` 가 지금 적용 중인 한도

**아래 토큰 수치와는 다른 값이다.** 토큰 바는 *내 세션 기록을 세서* 만든 것이고,
이건 *서버가 알려주는 남은 한도*다. 같아질 이유가 없다.

### 어디서 오나

`~/.claude/.credentials.json` 의 OAuth 토큰으로
`https://api.anthropic.com/api/oauth/usage` 에 물어본다. Windows 는 토큰이 파일에
있어 파일만 읽으면 된다. 응답의 `five_hour` · `seven_day` · `limits[]` 를 게이지로 만든다.

> **비공식 endpoint 다.** 형태가 바뀌거나 막히면 한도 칸만 조용히 사라지고
> 나머지는 그대로 돈다. 오류를 화면에 띄우지 않는다.

토큰은 `Authorization` 헤더에만 싣는다. 로그·응답·캐시 어디에도 남기지 않고,
밖으로 나가는 건 퍼센트와 시각뿐이다. 토큰이 만료되면(Claude Code 가 곧 갱신한다)
그동안만 칸이 숨는다.

호출은 서버에서 **1분 캐시**한다(실패하면 5분). 화면이 더 자주 물어도 endpoint 는
1분에 한 번만 두드린다. 작업이 끝나면(`Stop` 훅) 2초 뒤 한 번 더 본다.

## 토큰 사용량 (헤더)

헤더 오른쪽에 **오늘 / 최근 5시간 / 출력·입력** 세 칸이 붙어 있다. 마우스를 올리면
입력·출력·사고·캐시 쓰기(1시간/5분)·캐시 읽기·응답 수, 모델별, 프로젝트별 내역이 나온다.

별도 계측을 하지 않는다. 이미 스캔하고 있는 세션 기록에서 `type:"assistant"` 라인의
`message.usage` 를 합칠 뿐이다.

```
~/.claude/projects/<슬러그>/<sessionId>.jsonl                  부모 세션
~/.claude/projects/<슬러그>/<sessionId>/subagents/*.jsonl      서브에이전트
```

집계할 때 걸리는 함정이 세 가지 있다 (`tokens.js` 주석에도 적어뒀다):

1. **같은 응답이 여러 번 기록된다.** 스트리밍·재개 과정에서 같은
   `message.id` 가 반복 기록되고 `output_tokens` 가 점점 커진다. 그래서
   `(message.id | requestId)` 별로 **합이 가장 큰 항목만** 남긴다. 먼저 나온 것을
   남기면 부분 출력만 잡혀 과소집계된다
2. **`<synthetic>` 모델 라인은 실제 호출이 아니다.** 제외한다
3. **`iterations[]` 는 내부 분해값이다.** 더하면 이중 계산이 되므로 최상위 값만 쓴다

캐시 읽기가 전체의 대부분을 차지하는 것은 정상이다. 대화가 길어질수록 매 호출마다
앞의 문맥을 캐시에서 다시 읽으므로 자연히 누적된다.

**단가는 표시하지 않는다.** 모델 단가는 바뀌고, 캐시 쓰기(1시간/5분)·캐시 읽기가
서로 다른 배율을 쓴다. 잘못된 표를 박아두면 틀린 금액을 자신 있게 보여주게 된다.

읽는 방식은 세션 스캐너와 같은 요령이다. jsonl 은 시간순 append 라 **파일 꼬리에서
2MB 를 읽고**, 관심 구간(오늘 0시 또는 5시간 전 중 이른 쪽)보다 오래된 항목이 나올
때까지 4배씩 최대 32MB 로 창을 넓힌다. `mtime` 이 그보다 오래된 파일은 열지도 않는다.
JSON 파싱 전에 `"usage"` 와 `"assistant"` 두 리터럴이 같은 줄에 다 있는지 먼저 본다.

갱신은 20초마다, 그리고 훅이 켜져 있으면 `Stop` 이벤트 직후에 한 번 더 한다.
`(mtime, size)` 로 캐시하므로 변한 파일만 다시 읽는다.

## 실행 상태 (작업 중 / 대기 중)

`~/.claude/sessions/<pid>.json` 을 읽는다. Claude Code 가 세션마다 직접 쓰는 파일로
`claude agents --json` 과 같은 원본이지만, 파일을 직접 읽으므로 즉시 응답한다(CLI 는 1.5초).

- 🟡 **작업 중**(busy) - 점이 깜빡인다
- 🟠 **승인 대기**(waiting) - Codex 세션에서만. 사람이 승인해줘야 진행된다
- 🔵 **대기 중**(idle) - 살아있고 입력 대기
- ⚫ 표시 없음 - 실행 중이 아님

죽은 프로세스가 남긴 파일은 `tasklist` 로 실제 claude.exe PID 와 20초마다 대조해 걸러낸다
(PID 재사용까지). 상태는 4초마다 갱신.

Codex 세션의 상태는 이 파일이 아니라 훅이 쓰는 별도 디렉터리에서 온다
(아래 `실시간 관측 (훅)` > `Codex` 참고). 두 출처를 `/api/live` 가 한 맵으로 합쳐
내려주므로 화면에서는 구분 없이 같은 점·같은 글자로 보인다.

**내장 터미널의 신원**도 provider 별로 다른 파일에서 온다. Claude 터미널은
`~/.claude/sessions/<pid>.json`, Codex 터미널은 `~/.codex/.cc-launcher-live/` 를
pid 로 역인덱스해서 찾는다 (훅이 남기는 pid 가 곧 우리가 띄운 codex 프로세스다).
provider 로 가르지 않으면 Codex 터미널이 자기 `sessionId` 를 못 찾아 세션 카드와
연결되지 않고, Windows 의 PID 재사용 때문에 죽은 Claude 세션의 상태·이름을 주워
그 Claude 카드가 Codex 터미널을 가리키는 일까지 생긴다.

## 연결 그래프

프로젝트 → 세션 → 서브에이전트 3단 계층. 위쪽 밴드에 전역 MCP 서버를 따로 뺐다
(모든 프로젝트에 걸려서 엣지로 그리면 헤어볼이 된다 - 실측 133개였다).

- 실행 중 세션은 금색 엣지, 대시보드 터미널은 파란 테두리
- 세션 클릭 → 대화 패널, 대시보드에서 도는 세션 → 그 터미널로 이동
- 서브에이전트 엣지 굵기는 호출 횟수. `subagent_type` 을 세션 기록 전체에서 훑는다
  (앞/끝 표본으로는 놓친다). mtime 캐시라 두 번째부터는 34ms

**서브에이전트 계층은 Claude 세션에만 그려진다.** Codex 세션은 그래프에 노드로는
올라오지만 서브에이전트 엣지가 항상 0개다. Codex 쪽 부모-자식 관계는
`threads.source` 의 `subagent.thread_spawn.parent_thread_id` 에 들어 있고 어댑터가
`parentId` 로 뽑아서 API 로 내보내기까지 하지만, 그래프가 그 값을 읽지 않는다
(`thread_spawn` 조인이 아직 구현돼 있지 않다). 실황 타임라인의 레인도 마찬가지다.

## 구성 (하네스)

Claude Code 설정은 여러 파일에 흩어져 있다. 그걸 한 장으로 합쳐서 **어디서 온 설정인지까지**
같이 보여준다.

```
~/.claude/settings.json                 권한·모델·노력수준·플러그인 on/off
~/.claude.json                          전역 MCP 서버 + 프로젝트별 신뢰/MCP 사용 여부
<project>/.claude/settings.json         프로젝트 공유 설정
<project>/.claude/settings.local.json   내 로컬 설정
<project>/.mcp.json                     프로젝트 MCP 서버
~/.claude/plugins/...                   플러그인이 등록하는 훅·스킬·에이전트·명령
~/.claude/skills, ~/.claude/agents
```

**훅** 은 이벤트별로 묶어서 matcher·실제 명령·출처를 보여준다. `command` 와 `args` 가
분리된 형식(`"node"` + `["...script.mjs"]`)도 합쳐서 뭐가 도는지 보이게 한다.
꺼진 플러그인의 훅은 흐리게 + `꺼짐` 으로 표시된다.

### 점검 결과

| 항목 | 무엇을 잡나 |
|---|---|
| 권한 규칙의 위험한 와일드카드 | `Bash(...)` 커맨드 **중간**의 `*`. 그 자리에 끼워넣은 옵션까지 자동 승인된다. Claude Code 자신이 경고하는 것과 같은 기준이라 `Read(.../**)` 같은 정상 글롭은 제외한다 |
| 대소문자만 다른 중복 프로젝트 경로 | `C:/foo` 와 `c:/foo` 가 따로 등록되면 신뢰·MCP·허용툴 설정이 두 곳으로 갈린다 |
| 꺼진 플러그인의 훅 | 플러그인이 꺼져 있으면 등록된 훅이 안 도는데 헷갈리기 쉽다 |
| 이름이 겹치는 스킬 | 같은 이름이 두 곳에 있으면 하나가 가려진다 |
| 없는 디렉터리 | `additionalDirectories` 에 이제 존재하지 않는 경로 |
| 신뢰 미승인 프로젝트 | `hasTrustDialogAccepted` 가 아직 false |

### Codex (읽기 전용)

Codex 쪽은 `~/.codex/config.toml` 을 직접 파싱하지 않는다. Node 에 내장 TOML
파서가 없고, 이 프로젝트는 새 npm 의존성을 추가하지 않는다는 원칙이 있어서다.
대신 `codex doctor --json` 이 설정·MCP·인증·경로 점검 결과를 이미 평평한 JSON으로
주므로 그걸 그대로 보여준다 (실측 24개 체크 - app-server·auth·config·mcp·network·
security·terminal 등 카테고리 태그가 항목마다 붙는다). 경고/실패가 있는 항목을
앞으로 정렬해서 보여준다.

**편집 컨트롤이 없다.** 구성 탭의 [읽기 전용 | 편집] 스위치는 Claude 쪽에만 적용된다.

**버튼을 눌렀을 때만 부른다.** `codex doctor` 는 네트워크 도달성(reachability)까지
확인해서 수 초가 걸린다. 구성 로딩과 분리해 두는 이유는 Claude 쪽 MCP 연결 상태
확인(15.3초, 성능 표 참고)을 버튼 뒤로 뺀 것과 같다.

## 실황 (타임라인)

**실황** 탭. 세션과 서브에이전트가 무엇을 언제 했는지 워터폴로 그린다.

```
cc-launcher            ▬▬▬  ▬▬▬▬   ▬▬     ▬▬▬▬     ← 부모 세션
                            ▬▬▬             ▬▬     ← 병렬 호출은 서브행으로 쌓인다
  └ Explore #1              ━━━━━━━━━            ← 에이전트 생존 구간
                              ▬                  ← 그 에이전트가 돌린 툴
  └ Explore #2                    ━━━━━━━
```

- **레인**: 부모 세션 아래에 서브에이전트가 들여쓰여 붙는다. 같은 종류가 여럿이면 `#1 #2` 로 번호
- **막대**: 툴 호출 하나. 색은 읽기/쓰기/실행/에이전트/MCP/네트워크로 구분, 실패는 빨강.
  진행 중인 건 오른쪽(지금)까지 늘어나며 깜빡인다
- **겹침**: 병렬 툴 호출은 레인 안에서 서브행으로 쌓는다 (구간 패킹)
- **마커**: 프롬프트(주황 점선) / 응답 완료(초록)
- **시간 폭**: 30초 / 2분 / 10분 / 30분. `⏸ 멈춤` 으로 정지
- **최근 턴**: 프롬프트 → 툴 몇 개 · 서브에이전트 몇 개 · 소요시간

막대에 마우스를 올리면 툴 이름 · 실제 소요시간 · 명령 요약 · 어느 에이전트 소속인지 나온다.

### 부모와 자식을 어떻게 가르나

훅이 주는 필드로 정확히 갈린다. 추정이 아니다:

| 필드 | 뜻 |
|---|---|
| `session_id` | 부모 세션. **서브에이전트가 돌 때도 부모 값이 온다** |
| `agent_id` | 서브에이전트가 돌린 작업에만 붙는다 (부모 작업엔 없음) |
| `agent_type` | 서브에이전트 종류 (`Explore`, `code-reviewer` …) |
| `tool_use_id` | PreToolUse ↔ PostToolUse 짝짓기 |
| `duration_ms` | PostToolUse 의 실제 소요시간 (훅 왕복 지연이 안 섞인 값) |
| `prompt_id` | 한 프롬프트에서 파생된 모든 활동의 묶음 = 턴 |

실측 예 — 부모가 에이전트를 띄우고, 둘이 동시에 일하는 게 그대로 보인다:

```
PostToolUse  PowerShell  (부모)      부모 작업
PreToolUse   Agent       (부모)      부모가 서브에이전트 스폰
SubagentStart            a3a29803    자식 시작
PreToolUse   Bash        a3a29803    자식이 자기 툴 실행
PreToolUse   Bash        (부모)      부모는 병렬로 자기 일
SubagentStop             a3a29803    자식 종료 (결과 문장 포함)
```

`/api/events/keys` 로 훅이 실제로 보내는 필드를 이벤트별로 확인할 수 있다.

## 연결 그래프의 실시간 신호

**연결** 탭은 구조(프로젝트 → 세션 → 서브에이전트)를 그대로 두고, 이벤트가 올 때
해당 엣지를 따라 **신호가 달린다.**

- **갈 때 / 올 때가 방향으로 갈린다** — 요청은 오른쪽으로, 결과는 왼쪽으로 되돌아온다.
  `SubagentStop` 은 에이전트에서 세션으로 돌아오는 신호다
- 신호 색은 툴 종류(읽기·쓰기·실행·MCP·에이전트), 실패는 빨강, 승인 대기는 주황
- 활동 중인 세션의 엣지는 **점선이 계속 흐른다**
- 그래프에 없는 새 에이전트 종류가 등장하면 그래프를 다시 만들어 노드를 추가한다
- SVG `animateMotion` + `mpath` 를 쓰므로 JS 타이머가 없다. 신호는 끝나면 DOM 에서 제거되고
  동시 표시는 70개로 제한한다
- 보고 있지 않은 탭에는 신호를 쏘지 않는다 (불필요한 렌더 방지)

## 구성 편집 (쓰기)

구성 탭 맨 위의 **[읽기 전용 | 편집]** 스위치. 기본은 읽기 전용이고, 편집을 켜야 컨트롤이 나온다.

| 대상 | 할 수 있는 일 |
|---|---|
| 모델 · 노력 수준 | 드롭다운으로 변경 |
| 권한 규칙 | 추가 / 개별 삭제. 추가할 때 위험한 와일드카드면 경고를 띄운다 |
| 추가 디렉터리 | 추가 / 삭제. 없는 폴더는 추가를 거부한다 |
| 플러그인 | 켜기 / 끄기 (`claude plugin enable|disable`, 실패 시 설정 직접 수정) |
| MCP 서버 | 추가 / 제거 (`claude mcp add|remove`), 연결 상태 확인, 프로젝트별 on/off |
| 에이전트 | 만들기(이름·설명·도구·모델 폼) / 내용 편집 / 휴지통으로 이동 |
| 스킬 | 만들기(이름·설명) / 내용 편집 / 휴지통으로 이동 |
| 되돌리기 | 백업 목록에서 골라 `settings.json` 을 그 시점으로 복원 |

### 설정 대상 (스코프)

편집은 **어느 파일에 쓸지** 골라서 한다. 위가 아래를 덮는다:

| 스코프 | 파일 | 누구에게 |
|---|---|---|
| **프로젝트 로컬** | `<프로젝트>/.claude/settings.local.json` | 나 · 이 프로젝트 (커밋 안 됨) |
| **프로젝트 공유** | `<프로젝트>/.claude/settings.json` | 팀 전체 (커밋됨) |
| **전역** | `~/.claude/settings.json` | 나 · 모든 프로젝트 |

- 프로젝트 스코프를 고르면 프로젝트 선택 드롭다운이 나온다. 설정 파일이 아직 없는
  프로젝트도 고를 수 있고, 첫 저장 때 `.claude/` 와 파일을 만든다
- 각 항목에 **지금 실제로 적용되는 출처**가 태그로 붙는다 (`전역` / `프로젝트 공유` / `프로젝트 로컬` / `미설정`)
- 값을 `— 해제 —` 로 두면 그 스코프에서 키를 지워 **상위 스코프 값을 따르게** 되돌린다
- 아무 폴더에나 못 쓴다. 런처가 세션 기록으로 아는 프로젝트만 대상이 된다

### 서브에이전트 만들기

**팀으로 한 번에** — 자주 쓰는 조합을 골라 여러 개를 한 번에 만든다.
`뭘 만드는지 보기` 를 누르면 이름·모델·도구·설명과 저장 위치를 먼저 보여준다.

| 팀 | 구성 |
|---|---|
| 코드 리뷰 팀 | `reviewer` · `security-reviewer` · `test-writer` |
| 디버깅 팀 | `repro`(재현만) · `fixer`(수정) |
| 조사 · 문서 팀 | `explorer`(넓게 훑고 요약) · `doc-writer` |

이름 앞에 붙일 말(예: `hex-`)을 넣으면 프로젝트별로 갈라 쓸 수 있다.
**이름이 겹치면 그것만 건너뛰고 나머지는 만든다** — 하나 때문에 팀 전체가 막히면 더 답답하다.

**하나씩 만들 때** 도구는 체크박스로 고른다. 하나도 안 고르면 전체 허용이다.

**저장 위치는 위의 `설정 대상` 을 따른다.**

| 스코프 | 어디에 |
|---|---|
| 전역 | `~/.claude/agents/<이름>.md` |
| 프로젝트 공유 · 프로젝트 로컬 | `<프로젝트>/.claude/agents/<이름>.md` |

에이전트에는 `settings.json` 같은 공유/로컬 구분이 없다 — 폴더가 `.claude/agents` 하나뿐이라
둘 다 같은 곳으로 간다.

> 만든 것은 **뼈대**다. 프론트매터(`name`/`description`/`tools`/`model`)와 빈 목차까지만
> 채워 두므로, `편집` 으로 내용을 채워야 쓸 만해진다.
> `description` 이 곧 선택 기준이다 — Claude 가 이 문장을 보고 언제 부를지 정한다.
> **다음 세션부터 인식된다.**

### 시각 설정 편집기

`설정` 섹션에서 24개 항목을 드롭다운·켬/끔/해제·숫자·텍스트로 만진다.
문서(`settings-reference`)에 있는 키만 넣는다 — 없는 키를 써도 조용히 무시되므로 위험하다.

**기본**: 모델 · 노력 수준 · 기본 권한 모드 · 세션 기본 에이전트 · 응답 언어

**멀티 · 서브에이전트**:

| 항목 | 키 | 비고 |
|---|---|---|
| 에이전트 팀 | `env.CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` | **실험 기능·기본 꺼짐.** 켜야 팀원끼리 직접 메시지·공유 작업목록을 쓴다 |
| 서브에이전트 모델 | `env.CLAUDE_CODE_SUBAGENT_MODEL` | `inherit` = 메인과 같은 모델 |
| 모델 강제 | `env.CLAUDE_CODE_SUBAGENT_MODEL_FORCE` | 에이전트 정의의 `model` 무시 |
| 동시 상한 | `env.CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` | 기본 20 |
| 중첩 깊이 | `env.CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` | 기본 3 |
| 팀원 표시 방식 | `teammateMode` | 분할 패인은 tmux/iTerm2 필요 — **Windows Terminal 미지원** |

위 다섯 개는 설정 키가 아니라 `env` 환경변수라서 `env` 객체에 들어간다.

**스코프별 경고**도 표시한다 — 예: `permissions.defaultMode` 의 `auto`·`bypassPermissions` 는
프로젝트 설정에서는 적용되지 않는다.

### 안전 장치

모든 쓰기에 공통으로 걸린다 (`config-write.js`):

1. **백업** — 고칠 때마다 `<파일>.bak_YYYYMMDD_HHMMSS` 를 남긴다. 같은 초에 두 번 쓰면
   뒤에 번호를 붙여 앞 백업을 덮지 않는다. 백업 목록과 되돌리기는 **스코프별로 분리**돼 있어
   전역 백업을 프로젝트 파일에 복원하는 사고가 막힌다
2. **원자적 쓰기** — 임시 파일에 쓰고 **다시 파싱해 검증한 뒤** rename 으로 교체한다.
   반쯤 쓰인 설정 파일이 남지 않는다
3. **삭제 대신 휴지통** — 에이전트·스킬 삭제는 `~/.claude/.cc-launcher-trash/<시각>_<이름>/` 으로
   옮긴다. 파일이 사라지지 않으므로 되돌릴 수 있다
4. **타입 고정** — 임의 JSON 을 받지 않는다. `op` 마다 허용 키·허용값이 정해져 있고,
   바꿀 수 있는 설정 키는 화이트리스트(`model`, `effortLevel`, `autoUpdatesChannel`, `tui`)뿐이다.
   `permissions` 를 통째로 덮어쓰는 요청은 거부된다
5. **경로 검증** — 이름은 `[A-Za-z0-9][A-Za-z0-9._-]{0,63}` 만 통과한다. `../` 같은 경로 탈출과
   백업 파일명 위조(`../../settings.json`)를 막는다
6. **확인 대화** — 삭제·되돌리기는 브라우저 confirm 을 거친다

MCP·플러그인은 **공식 CLI 에 맡긴다.** 형식 검증을 우리가 다시 구현하지 않는 게 안전하다.

### 알아둘 점

- 설정 변경은 대부분 **다음 세션부터** 적용된다 (돌고 있는 세션에는 반영되지 않는다)
- 새로 만든 에이전트·스킬도 다음 세션부터 인식된다
- MCP **연결 상태 확인**은 `claude mcp list` 가 서버를 전부 헬스체크해서 15초쯤 걸린다.
  그래서 구성 로딩과 분리해 버튼을 눌렀을 때만 실행한다
- 플러그인이 제공하는 스킬·에이전트는 편집·삭제 버튼이 나오지 않는다 (플러그인 소유)

## 실시간 관측 (훅)

Claude Code 의 **`type:"http"` 훅**을 이 서버로 걸면, 세션이 지금 무슨 툴을 돌리는지·
서브에이전트가 언제 뜨고 끝나는지가 연결 탭에 실시간으로 흐른다.

**프로세스를 띄우지 않는다.** Claude Code 가 `http://127.0.0.1:7788/api/hook` 으로 직접
POST 하고 서버는 즉시 200 을 돌려준다 (실측 이벤트당 ~8ms, 첫 연결만 67ms).
스크립트를 실행하는 `type:"command"` 훅은 이벤트마다 node 프로세스를 띄워
50~80ms 가 붙기 때문에 쓰지 않았다.

### 설치

연결 탭의 배너에서 버튼으로 켠다. 또는:

```
node hooks-install.js status            # 현재 상태
node hooks-install.js install           # 세션·에이전트 이벤트만
node hooks-install.js install full      # 툴 단위까지 전부
node hooks-install.js uninstall         # 제거
```

`~/.claude/settings.json` 의 `hooks` 에 항목을 넣는다. 쓰기 전에 타임스탬프 백업
(`settings.json.bak_YYYYMMDD_HHMMSS`)을 만들고, 임시 파일에 쓴 뒤 **다시 파싱해 검증하고**
교체한다. 우리가 넣은 항목은 url 로 식별하므로 직접 넣은 훅은 건드리지 않는다.

| 모드 | 걸리는 이벤트 |
|---|---|
| 세션·에이전트 (기본) | SessionStart/End, UserPromptSubmit, Stop, StopFailure, SubagentStart/Stop, Notification, PreCompact/PostCompact |
| 툴까지 전부 | 위 + PreToolUse, PostToolUse, PostToolUseFailure |

### 보이는 것

- **실시간 활동 피드** — 이벤트별 색 구분(프롬프트/툴/에이전트/알림/실패), 시각·프로젝트 표시
- **그래프 노드 실시간 갱신** — 세션 라벨이 `Bash · 에이전트 2` 처럼 지금 상태로 바뀌고,
  작업 중인 노드는 금색으로 깜빡인다. 그래프를 다시 그리지 않고 노드만 고치므로 스크롤이 튀지 않는다
- **단계 추론** — `대기 중 / 생각 중 / 툴 실행 중 / 승인 대기`.
  `Notification: permission_prompt` 가 오면 **승인 대기**로 잡히니, 어느 세션이 사람을
  기다리는지 바로 보인다
- 연결 탭 배지에 활동 중인 세션 수

### 알아둘 점

- **훅은 새로 시작하는 세션부터 붙는다.** 이미 돌고 있는 세션에는 적용되지 않는다
- **런처를 껐는데 훅이 설치돼 있으면** 훅이 연결 실패로 오류 알림을 남길 수 있다
  (연결 거부는 즉시 실패하므로 세션이 멈추지는 않는다). 런처를 안 쓸 거면
  `node hooks-install.js uninstall` 로 빼는 게 깔끔하다
- 훅 본문은 `tool_result` 때문에 커질 수 있어 12MB 까지 받고, 저장은 항목당 400자로 자른다
- SSE 가 끊기면 브라우저가 알아서 재접속한다 (피드 헤더에 `연결됨 / 끊김` 표시)

### Codex

Codex 의 훅 설정 스키마는 핸들러 종류를 4개(`command`, `mcp_tool`, `prompt`, `agent`)
받아들이지만, 공식 문서 기준 `prompt` 와 `agent` 는 파싱만 되고 실행되지는 않는다.
그래서 실제로 동작하는 건 `command` 와 `mcp_tool` 뿐이고, **`http` 핸들러는 아예
없다.** Claude 쪽처럼 프로세스 없이 직접 POST 할 방법이 없다는 뜻이라, 이벤트마다
작은 브리지 스크립트 `codex-hook.js` 를 실행해 그 프로세스가 대신 런처로 POST 한다.

`~/.codex/hooks.json` 에 이벤트 12개를 건다 - SessionStart/End, UserPromptSubmit,
PreToolUse/PostToolUse, PermissionRequest, SubagentStart/Stop, Stop, Interrupt,
PreCompact/PostCompact. 대부분은 `"async": true` 로 걸어 스크립트 프로세스가 뜨는 동안
에이전트 턴이 막히지 않게 한다. SessionEnd·Interrupt 두 개만 동기(타임아웃 3초)로
남겨 상태 파일이 확실히 정리되게 한다.

Codex 에는 `~/.claude/sessions/<pid>.json` 같은 대응물이 없어서, `codex-hook.js`
가 직접 `~/.codex/.cc-launcher-live/<session_id>.json` 에 실행 상태를 쓰고
SessionEnd 때 그 파일을 지운다.

이 상태는 `/api/live` 가 Claude 상태와 **한 맵에 합쳐서** 내려준다. 프론트의 4초
폴링은 provider 를 가리지 않고 `live[sessionId]` 를 그대로 붙이므로, 여기서 Codex 를
빼면 훅이 만들어 준 상태가 4초마다 지워진다. 두 provider 의 id 가 겹칠 일은 없지만
항목마다 `provider` 를 실어 보내고 프론트가 자기 provider 것만 붙인다.

`waiting`(승인 대기)은 Codex 훅의 `PermissionRequest` 에서만 나오는 상태다. 점은
주황색(`.st.wait`), 글자는 `승인 대기` 로 그린다 - 세션 행·세션 카드·프로젝트 카드
헤더·대화 패널 헤더·터미널 탭이 전부 같은 규칙을 쓴다.

**알려진 한계** - Claude 쪽은 `tasklist` 로 살아있는 claude.exe PID 를 대조해 죽은
프로세스가 남긴 상태 파일을 걸러내지만, Codex 쪽은 이 대조를 하지 않는다. Codex
프로세스가 SIGKILL 로 죽으면 SessionEnd 훅 자체가 실행되지 않으므로 상태 파일이
지워지지 않고, 파일에 찍힌 시각이 24시간을 넘기 전까지는 이미 죽은 세션이
**작업 중**으로 잘못 표시될 수 있다. 관측을 끄면(`uninstall`) 이 디렉터리를 통째로
지우므로, 훅이 사라진 뒤에 상태가 굳어 남는 일은 없다.

설치/제거는 연결 탭 배너의 버튼으로만 한다 - `codex-hooks-install.js` 는 (Claude 쪽
`hooks-install.js` 와 달리) CLI 진입점이 없고 서버가 함수를 직접 호출한다. 안전장치는
Claude 쪽과 같다: 쓰기 전 타임스탬프 백업, 임시 파일에 쓴 뒤 재파싱 검증, 우리 항목만
`statusMessage` 로 식별해서 직접 넣은 훅은 건드리지 않는다.

되돌리기는 **완전해야 한다**. 그래서 제거는 두 가지를 더 지킨다.

- `hooks.json` 이 애초에 없으면 아무것도 하지 않는다. 지울 게 없는데 `{}` 만 든
  파일을 새로 만들면 없던 사용자 상태를 만들어내는 셈이다
- `.cc-launcher-live/` 디렉터리를 통째로 지운다. 그 파일을 지우는 건 `SessionEnd`
  훅인데 방금 그 훅이 사라졌으므로, 남겨두면 지울 수단이 없다

반대로 **첫 설치는 백업이 없는 게 정상이다** (`backup: null`) - 고칠 원본 파일이
없기 때문이다. 성공/실패를 백업 경로의 유무로 판단하면 안 된다.

## 대화 보기

세션 행이나 `대화 보기` 를 누르면 오른쪽 패널에 대화가 열린다.

- 나 / Claude(Codex 세션이면 `Codex`) / 도구 / 생각 구분 + 타임스탬프,
  볼드·헤딩·불릿·코드블록 렌더링
- 실행 중인 세션이면 5초마다 자동 갱신
- 기본 40개, `더 불러오기` 로 300개까지
- 18MB 세션도 0.3초 (파일 끝 3MB만 읽는다)
- Codex 세션은 jsonl 이 아니라 rollout 파일(`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`)을
  읽는다. **여기도 파일 끝 3MB 상한이 걸려 있다** - rollout 은 실측 최대 9.4MB 인데
  살아있는 세션을 보고 있으면 5초마다 다시 읽고 다시 파싱하기 때문이다
  (mtime 캐시는 이 경우 매번 빗나가므로 도움이 안 된다)
- `threads.rollout_path` 는 일부 행이 확장 길이 경로(`\\?\C:\...`)로 저장돼 있어
  (실측 33행 중 4행) 어댑터에서 `cwd` 와 같이 접두사를 벗긴다. 안 벗기면 경로 검사에
  걸려 그 세션은 대화 보기도 토큰 집계도 안 된다

## 토큰 사용량

프로젝트 카드와 세션 행에 토큰 사용량 태그가 붙는다. 어디서 오는지가 Claude 와
Codex 가 서로 다르고, 그 차이 때문에 보여줄 수 있는 세부 내역도 다르다.

- **Claude** - 세션 jsonl 의 메시지마다 붙는 `usage` 레코드를 전부 더한다
  (실측 예: 세션 하나에서 2,309개). 입력·출력·캐시쓰기·캐시읽기 내역이 그대로 나온다
- **Codex** - rollout jsonl 끝의 `token_count` 이벤트에 들어 있는 `total_token_usage`
  레코드를 읽는다. 이 레코드는 턴마다 **누계**로 다시 찍히므로 마지막 것 하나만 쓴다
  (더하면 안 된다). 여기에도 입력·출력·캐시읽기·캐시쓰기 내역이 다 들어 있다

**`cache_read_input_tokens` 은 billable 합계에서 뺀다.** 이 값은 매 턴 같은 컨텍스트를
다시 읽는 값이라, 세션 전체에 걸쳐 그대로 더하면 실제 소비량을 크게 부풀린다.
합계와 분리해서 툴팁에 따로 보여준다.

**두 provider 가 같은 정의를 쓴다** - `billable = 비캐시 입력 + 출력 + 캐시쓰기`.
그래서 프로젝트 카드의 합계처럼 Claude 와 Codex 를 더해도 의미가 있다. 이걸 맞추려면
Codex 쪽에서 한 번 변환이 필요하다: **Codex 의 `input_tokens` 는 `cached_input_tokens`
를 포함한 값이다** (실측: `total_tokens === input_tokens + output_tokens`). Claude 의
`input_tokens` 는 반대로 캐시 읽기를 이미 뺀 값이다. 그래서 Codex 쪽만 캐시분을 빼낸다.

**`threads.tokens_used` 컬럼은 쓰지 않는다** (rollout 을 못 읽을 때의 폴백일 뿐이다).
그 값은 캐시 입력까지 포함한 세션 총량이라 위 정의와 같은 자로 잰 값이 아니다 -
실측 한 세션에서 `tokens_used` 26,078,648 중 24,819,456(95%)이 캐시 입력이었고,
같은 세션의 billable 은 1,259,192 이다 (약 20배 차이). 폴백이 쓰인 세션은 사용량
태그가 빨갛게 표시되고 툴팁이 "캐시 입력 포함이라 Claude billable 과 같은 기준이
아니다" 라고 말한다. 프로젝트 합계 툴팁에도 섞여 있다는 사실이 적힌다.

**`scan()` 과 분리된 별도의 `/api/usage` 엔드포인트다.** Claude 쪽 사용량은 세션
파일을 통째로 읽어야 나오는데, `scan()` 은 앞부분 몇 KB·끝 256KB만 읽도록 일부러
설계돼 있다 (아래 성능 참고). 그래서 `scan()` 에 얹지 않고 요청이 왔을 때만 계산해서
파일별로 캐시한다 (mtime+size 로 무효화). Codex 도 같은 자리에서 같은 방식으로
캐시하되, rollout 은 끝 256KB 만 읽는다 (실측: 마지막 `token_count` 는 EOF 에서
3KB 안쪽이다).

## 버튼

| 버튼 | 하는 일 |
|---|---|
| 이어하기 | `claude --resume <id>` (실행 위치 설정에 따라 대시보드 / 새 창) |
| 포크 | `claude --resume <id> --fork-session` (원본 보존) |
| 최근 이어하기 (Claude) | `claude --continue` |
| 최근 이어하기 (Codex) | `codex resume --last` |
| 새 세션 | `claude` |
| 터미널로 이동 | 이미 대시보드에서 돌고 있는 세션이면 그 터미널로 점프 |
| 창 띄우기 | 외부 창에서 돌고 있는 세션의 터미널 창을 앞으로 |
| 📁 / VS Code | `explorer` / `code <cwd>` |

이미 실행 중인 세션은 `이어하기` 가 나오지 않는다 - 같은 세션을 두 번 열면
Claude Code 가 거부하기 때문에, 대신 이동/포커스 버튼으로 바뀐다.

Codex 세션은 같은 버튼이 다른 명령을 쓴다: 이어하기 `codex resume <id>`, 포크
`codex fork <id>`, 최근 이어하기 `codex resume --last`, 새 세션 `codex`.
실행 위치(대시보드 / 새 창)는 Claude 와 똑같이 헤더 설정을 따른다.
프로젝트 카드 아래쪽의 `최근 이어하기` 와 `새 세션` 은 provider 별로 버튼이
따로 있고, `codex` 를 PATH 에서 못 찾으면 Codex 쪽 버튼이 비활성으로 나온다.

## 단축키

- `/` 검색창 포커스 · `Enter` 첫 세션 열기 · `Esc` 검색 초기화 / 패널 닫기
- 검색: 프로젝트명 · 경로 · 세션 제목 · 첫/마지막 프롬프트 공백 구분 AND
- 터미널에 포커스가 있으면 전역 단축키는 동작하지 않는다 (키를 PTY 가 받는다)
- 터미널 복사/붙여넣기: `Ctrl+V` 붙여넣기 · 선택이 있을 때 `Ctrl+C` 복사(없으면
  평소대로 SIGINT) · `Ctrl+Shift+C` 복사(선택 없으면 SIGINT 로 안 내려가고 키 입력만
  무시된다) · 우클릭은 선택이 있으면 복사, 없으면 붙여넣기

`server.js` 는 맨 위에서 `node:sqlite` 의 `ExperimentalWarning` 하나만 걸러낸다.
`--no-warnings` 로 통째로 끄면 진짜 봐야 할 deprecation 경고까지 사라지고, `run.bat` /
`run-hidden.vbs` 에 플래그를 넣으면 `npm start` 로 띄웠을 때는 또 경고가 뜬다.
서버 진입점에서 거르면 어떻게 띄우든 결과가 같다.

세션 파일을 통째로 읽지 않는다. 앞부분에서 `cwd`·제목·첫 프롬프트를, 끝 256KB 에서
마지막 프롬프트를 뽑는다. `file-history-snapshot` 같은 거대 레코드가 앞을 막고 있으면
최대 2MB까지 창을 넓혀가며 읽는다. 그래프의 서브에이전트 스캔만 파일 끝 24MB 를 훑는다.
Claude 쪽 토큰 사용량만 예외로 파일을 통째로 읽는다 (`usage` 레코드가 메시지 전체에
흩어져 있어 부분 읽기로는 못 뽑는다) - 그래서 `scan()` 에 얹지 않고 `/api/usage` 로 분리했다.
Codex 쪽은 통째로 읽지 않는다: 사용량은 rollout 끝 256KB, 대화 보기는 끝 3MB 만 읽는다.

## 주의

- **이 서버는 claude 프로세스를 띄우고 PTY 입력을 전달한다.** 그래서 `127.0.0.1` 에만
  바인딩하고, POST 와 WebSocket 업그레이드 모두 Origin 을 검사한다. 절대 외부에 포워딩하지 말 것.
- **서버를 Ctrl+C 로 끄면** 내장 터미널의 claude 프로세스도 함께 정리된다.
  창을 X 로 강제 종료해도 ConPTY 자식은 부모와 함께 죽지만, 확인하려면
  `tasklist /FI "IMAGENAME eq claude.exe"` 로 본다.
- 내장 터미널을 ✕ 로 닫으면 그 세션은 **종료**된다. 대화 기록은 남으므로 나중에 이어할 수 있다.
- 세션 파일 경로는 화이트리스트 정규식으로만 받는다 (경로 탈출 차단).
- 폴더가 삭제된 프로젝트는 흐리게 + `폴더 없음` 으로 표시되고 실행이 막힌다.
- 이 런처를 더 안 쓸 거면 Claude 훅뿐 아니라 Codex 훅도 함께 빼는 게 깔끔하다
  (Claude 는 `node hooks-install.js uninstall`, Codex 는 연결 탭 배너 버튼으로 - 전용 CLI 는 없다).
