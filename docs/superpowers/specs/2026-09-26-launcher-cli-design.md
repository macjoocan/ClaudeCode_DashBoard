# 런처 CLI 설계 — 2026-09-26

## 무엇을 만드나

대시보드는 **브라우저 그대로** 쓴다. 바뀌는 건 내장 터미널 패인 하나다. 지금은 패인을
열면 `claude` 나 `codex` 가 바로 뜨는데, 그 자리에 **런처 CLI** 가 먼저 뜨고 거기서
어느 쪽이든 골라 들어간다.

목적은 provider 를 늘리는 것도, 브라우저를 대체하는 것도 아니다. **Codex 와 Claude 를
한 입구에서 고르는 것**이다.

성공 기준:

- 패인을 열면 CLI 가 뜨고, 이 폴더의 세션이 provider 구분 없이 한 목록에 보인다
- 하나 골라 Enter 치면 그 패인이 **그대로 그 에이전트가 된다** — 화면 쓸림 없이
- 머리글의 `런처` 버튼으로 CLI 로 돌아온다
- 서버가 꺼져 있으면 조용히 실패하지 않고 이유를 말한다

## 왜 중계하지 않나

세 가지를 놓고 C 를 택했다.

| | 방식 | 문제 |
|---|---|---|
| A | CLI 가 살아서 에이전트 입출력을 중계 | **TUI 가 두 겹이 된다** |
| B | CLI 가 `exec` 로 자리를 넘김 | 돌아올 방법이 없다 |
| **C** | B + 되돌리기는 **대시보드가** 한다 | — |

A 를 버린 이유가 제일 중요하다. 우리는 이미 그 대가를 치렀다: Codex 패인을 대체화면에
밀어넣었다가 **마우스 휠이 죽었고**(xterm 이 대체화면에서 휠을 화살표 키로 바꿔 앱에
보낸다), 이어하기 재생이 화면을 위에서 아래로 쓸었다. 중계 계층을 하나 더 얹는 것은
그 문제를 우리 손으로 다시 만드는 일이다. 자세한 내력은 README 의 터미널 절에 있다.

C 는 중계가 0 이다. 에이전트가 PTY 를 온전히 제 것으로 쓴다.

```
패인 열림  →  런처 CLI
                │  고르면: 대시보드에 알린 뒤 exec
                ▼
           claude / codex        ← 중계 없음. TUI 가 제 PTY 를 그대로 쓴다
                │  머리글 [런처] → POST /api/term/restart
                ▼
           런처 CLI 다시
```

되돌리기를 CLI 가 아니라 대시보드가 맡는 것이 C 의 요점이다. `exec` 한 프로세스는
스스로 돌아올 수 없지만, **패인의 주인은 서버**이므로 서버는 언제든 갈아끼울 수 있다.

## 이미 있는 것에 얹는다

새로 만드는 메커니즘이 거의 없다. 레포가 같은 문제를 이미 풀어뒀다.

| 필요한 것 | 이미 있는 것 |
|---|---|
| 패인의 명령을 갈아끼우기 | `terminals.restart(id, bins, freshStart)` — `/api/term/restart` 로 노출돼 있다 |
| 서버에 말 걸기 | `bridge-send.js` — 서버 내부를 import 하지 않고 HTTP 로만 붙는다 |
| 세션 목록·한도·전달 | `/api/graph` · `/api/limits` · `/api/bridge/send` |

CLI 도 같은 결을 따른다. **서버 모듈을 import 하지 않는다.** 대신 대시보드가 이미 아는
것을 다시 구현하지 않는다. 대가는 하나다 — **서버가 꺼져 있으면 CLI 도 못 쓴다.**
대시보드 안에서 여는 CLI 이므로 서버는 당연히 떠 있고, 그래도 꺼져 있으면
`bridge-send.js` 와 같은 문구로 거절한다.

## 밖에서 이미 하고 있는 것 (조사)

2026-09-26 확인. 같은 자리를 노리는 물건이 이미 있다.

| | 방식 | 스택 | 라이선스 | 별 |
|---|---|---|---|---|
| [ccmanager](https://github.com/kbwo/ccmanager) | PTY 직접(tmux 안 씀), TUI 메뉴, worktree 중심 | TS/Bun | MIT | 1.3k |
| [claude-squad](https://github.com/smtg-ai/claude-squad) | tmux + git worktree | Go | AGPL-3.0 | 8.5k |

`ccmanager` 가 우리와 같은 결이다 — PTY 를 직접 쥐고, tmux 없이, 에이전트별로
idle/busy/waiting 을 따로 판정한다. **겹치는 기능을 다시 만들 이유는 없다.**
우리가 만드는 것은 독립 도구가 아니라 **이미 있는 대시보드의 입구**이므로 범위가 다르다.

**둘 다 없는 것이 하나 있다**: 서로 다른 에이전트의 **살아있는 세션끼리 말을 주고받는
것**. claude-squad 는 독립 병렬 실행이 목적이라 아예 없고, ccmanager 에도 없다. 우리
`bridge.js`(도착 확인까지 붙은)가 그것이고, CLI 의 `전달` 화면이 그 위에 얹힌다.

## 새로 필요한 것 — `POST /api/term/provider`

이것 하나가 C 의 하중을 받는다.

터미널 레코드의 `provider` 는 `create` 할 때 한 번 정해지고 **안 바뀐다**:

```js
provider: isCodex ? 'codex' : 'claude',          // terminals.js, 생성 시 고정
```

그런데 그 값이 무엇을 읽을지를 결정한다:

```js
: (t.provider === 'codex' ? codexLiveInfo(t) : liveInfo(t.pid))   // 상태를 어디서 읽나
scrollback: info.provider === 'codex' ? 1000 : 8000               // 스크롤백
function repaintsInPlace(t) { return t && t.provider === 'codex'; } // 묶음 주기
```

패인을 `claude` 로 열어놓고 CLI 에서 `codex` 를 고르면 대시보드는 계속 Claude 인 줄
안다 — 상태 판정이 엉뚱한 곳을 읽고, 스크롤백은 8000 으로 남고, 덧그림 판정도 틀린다.

`sessionId` 는 문제가 아니다. 이미 훅이 남긴 live 상태에서 계속 갱신된다
(`terminals.js`: `if (live && live.sessionId) t.sessionId = live.sessionId;`).
**`provider` 만 고정이다.**

```
POST /api/term/provider   { id, provider, sessionId? }
  → t.provider 를 바꾸고
  → 붙어 있는 화면에 스크롤백·덧그림 설정을 다시 내린다
```

**CLI 는 이 호출이 성공한 뒤에만 `exec` 한다.** 실패하면 `exec` 하지 않고 이유를
띄운다 — 상태가 어긋난 채 넘어가면 사용자는 "왜 스크롤이 이상하지" 를 겪고 원인을
찾을 수 없다. 넘어가지 못하는 편이 낫다.

## CLI 가 하는 것

대시보드가 HTTP 로 이미 내주는 것만 쓴다.

| 화면 | 하는 일 | 쓰는 것 |
|---|---|---|
| 목록 | 이 폴더의 세션을 provider 구분 없이 한 줄씩 (● = 실행 중) | `GET /api/graph` |
| 고르기 | 위/아래로 고르고 Enter → 이어하기 | `POST /api/term/provider` → `exec` |
| 새로 | `n` → Claude/Codex 골라 새 세션 | 〃 |
| 한도 | 맨 위에 주간 % 두 줄 | `GET /api/limits` |
| 전달 | `s` → 반대편 세션에 말 보내기 | `POST /api/bridge/send` |
| 나가기 | `q` → 맨 셸로 | — |

의존성을 새로 넣지 않는다(레포 규칙). 화면은 ANSI 로 직접 그린다 — 목록 하나와 한도
두 줄이라 프레임워크가 필요한 규모가 아니다.

## 범위 밖

| | 왜 |
|---|---|
| worktree 관리 | `ccmanager` 영역이고, 패인 안에서 몇 초에 끝나는 일이 아니다 |
| 세션 삭제 | 되돌릴 수 없다. 대시보드에서 확인 절차를 거쳐 하는 편이 맞다 |
| 설정 편집 | 구성 탭이 있다 |
| `providers.js` 레지스트리 | **별개 작업으로 뗀다** — 아래 참고 |

`provider === 'codex'` 분기는 지금 9개 파일 26군데다. 읽어보면 진짜 차이는
대여섯(덧그림·스크롤백·묶음 주기·제출 방식·이어하기)이고 나머지는 라벨과 "아직 안
만든 것"이다. 한 표로 접을 값어치가 있다. **그러나 이 CLI 는 그것을 필요로 하지 않는다**
— CLI 는 provider 이름만 넘기고, 표를 읽는 쪽은 서버다. 같이 묶으면 리팩터링이 CLI 를
인질로 잡는다. 따로 한다.

## 오류

| | 어떻게 |
|---|---|
| 서버가 안 떠 있다 | `bridge-send.js` 와 같은 문구로 거절하고 끝낸다 |
| `provider` 알림 실패 | **`exec` 하지 않는다.** 사유를 띄우고 목록으로 돌아간다 |
| `exec` 실패 (바이너리 없음) | 사유를 띄우고 목록으로 돌아간다 — 패인이 빈 채로 죽지 않게 |
| `/api/graph` 가 느리다 | 목록 없이도 `n`(새로)은 되게 둔다 |

## 시험

CLI 는 화면을 그리는 물건이라 순수한 부분과 붙는 부분을 나눈다.

- **순수** — 세션 목록을 줄 문자열로 만드는 함수, 키 입력 → 다음 상태 전이.
  가짜 데이터로 시험한다. 터미널도 서버도 없이 돈다
- **엔드포인트** — `/api/term/provider` 가 `provider` 를 실제로 바꾸고, 붙어 있는
  화면에 설정을 다시 내리는지. 기존 `test/terminals.test.js` 결을 따른다
- **왕복** — **7788 은 건드리지 않는다.** 다른 포트로 서버를 띄워 확인한다
  (`CC_LAUNCHER_PORT=7899 node server.js`). 지금 7788 에는 사용자의 실제 작업 세션이
  붙어 있고, 서버를 내리면 **진행 중인 턴이 날아간다**

## 미해결

- **CLI 를 패인 기본 명령으로 할지, 옵션으로 할지.** 기본으로 하면 기존 "실행" 버튼의
  동작이 바뀐다. 헤더 토글(`실행 위치`)과 같은 결로 둘 수 있다. 결정 필요
- **키 바인딩.** 위/아래·Enter·`n`·`s`·`q` 로 잡아뒀는데 실제로 써보고 정한다
- **CLI 가 뜬 패인의 상태 표시.** 에이전트가 아니므로 idle/busy 판정 대상이 아니다.
  머리글에 무엇을 보여줄지 정해야 한다
