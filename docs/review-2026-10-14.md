## 안전 - 먼저 고칠 것

### 1. 대시보드 자동 Yes 에 위험 명령 필터가 없다
- 위치: `auto-yes.js` `approvalPrompt()`
- 팀 공유 훅(`tools/auto-yes`)은 `rm -rf`, `git push --force`, `git reset --hard`, `DROP TABLE`, 플랜 승인을 항상 사람에게 넘긴다. 대시보드 패인 버튼은 승인 메뉴면 다 누른다. 두 기능의 안전 기준이 다르다.
- 상황: 자동 Yes 를 켠 패인에서 에이전트가 `rm -rf build/ ..` 나 `git push --force` 를 실행하면 그대로 Enter 가 들어간다.
- 방향: 질문 위 명령 블록을 읽어 훅의 `ALWAYS_ASK_COMMANDS` 와 같은 목록으로 거른다. 목록은 한 곳에 두고 같이 쓴다.

### 2. 진짜 메뉴가 아닌데 눌릴 수 있다
- 위치: `auto-yes.js` 감지 규칙
- 출력 텍스트 매칭이라, 답변에 `Do you want to proceed? > 1. Yes  2. No` 같은 예시가 있으면 메뉴로 본다. Enter 가 들어가 입력창에 쓰던 글이 전송될 수 있다.
- 방향: 질문 줄 바로 아래 몇 줄 안에 선택지가 붙어 있고, 그 아래에 `Esc to cancel` / `Press enter to confirm` 같은 메뉴 꼬리가 있을 때만 메뉴로 본다.

### 3. 저장된 "묻지 않기" 권한이 경고 없이 다시 걸린다
- 위치: `server.js` `/api/term/new` (resume 때 `permStore.get`), `termsWithFavorites()` 의 `permStore.remember`
- 다시 열 때 저장된 `full` 을 확인 없이 적용한다. Codex 세션 ID 는 `codexSessionByCwd()` 로 폴더 기준 추정될 때가 있어, 추정이 틀리면 엉뚱한 세션에 `full` 이 기록된다.
- 방향: 추정 ID 는 저장하지 않는다(확정된 ID 만). 다시 열 때 저장값이 `full` 이면 화면에서 확인을 받는다.

## 기능 버그

### 4. 브리지 발신 세션 자동 선택이 자주 실패한다
- 위치: `mcp-bridge.js` `pickSource()`, `bridge-send.js`
- 같은 폴더에 live 세션이 2개 이상이면 에러. Codex live 표시는 최대 하루 남아 있어 끝난 세션 때문에 실패하기 쉽다. 옛 대체 규칙(아무 live -> 가장 최근)도 빠졌고 `bridge-send.js` 머리 주석은 옛 규칙을 그대로 말한다.
- 참고: 다른 세션이 만든 변경이다. "모호하면 에러" 가 의도인지 먼저 정한다.

### 5. 자동 Yes 가 스스로 꺼져도 버튼은 켜짐으로 보인다
